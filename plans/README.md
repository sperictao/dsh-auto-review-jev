  its own.
- Recommended order is the table order. 001 and 002 are small and independent;
  003 is the large one and pays off later (see "Deferred" below); 004 and 005
  are gate/docs work that can land any time.

  it only adds tests). Landing 001 before 002 keeps their `src/index.ts` hunks
  in different functions, which avoids a merge conflict if both are in flight.

## Findings considered and rejected

- **P0 — "the 0.1.7 dependency upgrade fails `pnpm typecheck` (5 errors)".**
  Not reproducible at HEAD. `pnpm typecheck` exits 0, `pnpm test` exits 0 (8
  files, 75 tests), `pnpm build` exits 0 at commit `1c758f6`. The audit's
  evidence was read from a stale working tree: the 0.2.7 commit completed the
  API migration (`ctx.settingsScope.bind` → `ctx.configForms.get`, the
  `compact-checkpoint` source kind, the removal of the two `tool-result`
  filters). Only the Cordis floor remained — that is plan 004.
- **P1 — "usage-refresh concurrency race in `refreshAccount`".**
  Not reproduced. `refreshAccount` (`src/usage-remote.ts:138`) re-checks
  `this.inFlight` *after* the credential await (line 147), and no `await`
  separates that check from the assignment on line 148, so two callers that
  both pass the first guard still coalesce onto one request. The cited line is
  the guard itself, not a bypass. Do not re-audit unless that second guard is
  removed.
- **P2 — "release metadata out of sync" (`package.json` 0.2.7 vs HEAD/tag/
  changelog at 0.2.6).** Resolved by commit `1c758f6`: `package.json` 0.2.7,
  tag `v0.2.7`, annotated, CHANGELOG section `## 0.2.7` at the top. Only the
  missing *gate* against recurrence remained, which is plan 005.
- **P2 — "DSH compatibility range too wide".** The peer ranges were already
  narrowed to `^0.1.7-alpha.1` at `1c758f6`; what remained is the Cordis floor
  (plan 004) and the missing support matrix (also plan 004).

## Deferred (not planned)

- **`src/index.ts` carries too many responsibilities (891 lines) and rebuilds a
  full review snapshot on every tool call** (`snapshotReview`,
  `src/index.ts:473`; called per call from `classify`, `src/index.ts:706`).
  Real, and the highest-value structural work here, but L effort with HIGH
  risk: `snapshotReview` is the authority model (`human-instruction` /
  `direct-parent-instruction` / `checkpoint` / `fact` roles) and a mistake there
  silently changes what authorizes a tool call. It must not be reorganized
  without the lifecycle tests of plan 003 in place first. Revisit after 003
  lands.
